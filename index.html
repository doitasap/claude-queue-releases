완료

왜 대기열이 필요한가

Claude Code를 오래 쓰면 마주치는 세 가지 상황이 있습니다.

한도에 걸려 멈춘다

작업 도중 사용 한도에 도달하면 거기서 멈춥니다. 리셋 시각에 맞춰 다시 자리에 앉아야 합니다.

순서를 사람이 지킨다

여러 프로젝트에 걸친 작업을 하나씩 확인하며 실행해야 합니다. 앞 작업이 끝났는지도 지켜봐야 합니다.

할 일이 흩어진다

"나중에 실행할 것"이 메모장·이슈·머릿속에 나뉘어 남습니다. 정작 여유가 생겼을 때 무엇부터 해야 할지 알기 어렵습니다.

ClaudeQueue는 이 세 가지를 하나의 대기열로 묶습니다. 한도에 걸린 항목은 리셋 대기로 남았다가 자동으로 재개됩니다. 순서는 큐가 지키고, 확정되지 않은 작업은 따로 보관됩니다.

3분 만에 시작하기

Claude Code CLI가 이미 설치돼 있다면 2단계부터 보시면 됩니다.

1

Claude Code CLI 설치

세 가지 방법 중 편한 것을 고르시면 됩니다. ClaudeQueue는 이 CLI를 실행합니다.

curl -fsSL https://claude.ai/install.sh | bash
brew install --cask claude-code
npm install -g @anthropic-ai/claude-code
claude --version

마지막 명령으로 버전이 출력되면 준비가 끝난 것입니다.

2

ClaudeQueue 설치 후 첫 실행

DMG를 내려받아 응용 프로그램 폴더로 옮긴 뒤 실행합니다. CLI를 찾지 못하면 앱이 설치 안내 화면을 먼저 띄우고, 설치를 마치고 다시 확인을 누르면 다음으로 넘어갑니다.

CLI를 특이한 위치에 설치했다면 설정에서 claude.bin에 절대 경로를 지정하시면 됩니다.

3

첫 작업 등록

프로젝트 경로를 고르고 실행할 명령을 적은 뒤 큐에 넣습니다. 자동 큐에 넣으면 위에서부터 순서대로 실행됩니다. 사람이 지켜보지 않아도 됩니다.

아직 확정되지 않은 작업이라면 대기·보류에 먼저 넣어 두십시오. 내용을 다듬은 다음 자동 큐로 승격하면 됩니다.

핵심 개념 세 가지

이 세 가지만 알면 나머지는 화면을 보며 익힐 수 있습니다.

① 두 개의 큐

자동 큐

위에서부터 순서대로 무인 실행됩니다. 같은 경로는 앞 항목이 끝나야 다음이 시작하고, 경로가 다르면 기본 세 곳까지 동시에 진행됩니다.

언제 쓰나 — 명령이 확정되어 지금 그대로 실행해도 되는 작업

대기 · 보류

보관·검토용 목록입니다. 여기 있는 항목은 저절로 실행되지 않습니다.

언제 쓰나 — 문구를 더 다듬어야 하거나, 지금 실행할지 판단이 안 선 작업

▲ 승격  /  ▼ 강등 — 두 큐 사이는 언제든 옮길 수 있습니다

② 두 종류의 실행 대상

경로 대상

지정한 프로젝트 디렉터리에서 새 작업을 시작합니다.

언제 쓰나 — 독립적인 새 작업을 시킬 때

세션 대상

기존 Claude 세션을 이어서 실행합니다. 앞선 맥락이 유지됩니다.

언제 쓰나 — 이전 대화의 결과를 놓고 후속 작업을 시킬 때

③ 체인 — 앞 작업을 이어받는 하위 항목

항목을 다른 항목 아래로 넣으면 체인이 됩니다. 부모가 완료된 뒤, 부모가 쓰던 세션을 이어받아 하위 명령이 실행됩니다. "빌드가 끝나면 그 결과를 요약해줘" 같은 흐름을 사람이 손대지 않아도 이어지도록 만들 수 있습니다.

사용량 링과 카운트다운

주간 한도 소진율을 링으로, 다음 리셋까지 남은 시간을 카운트다운으로 보여 줍니다. 같은 정보가 메뉴 막대 아이콘에도 표시되어 창을 닫아 두어도 확인할 수 있습니다. 갱신 주기는 설정의 usage_poll_secs를 따릅니다.

프로젝트 탭

여러 경로를 오갈 때 현재 프로젝트의 항목만 보이도록 걸러 냅니다. 전체 항목 표시를 켜면 모든 경로의 항목을 한 번에 볼 수 있습니다.

작업 번호

경로 칩 앞의 #12 같은 번호는 항목의 고유 번호입니다. 상태가 바뀌어도 그대로 남습니다. 파일이 겹쳤을 때 뜨는 알림이 "작업 #12 와 #15"처럼 이 번호로 대상을 가리키므로, 알림에 적힌 번호를 목록에서 그대로 찾으면 됩니다.

조작하기

목록에서 항목을 다루는 방법입니다. 마우스로 하는 조작과 버튼으로 하는 조작으로 나뉩니다.

드래그로 순서 변경 · 하위로 넣기

순서 변경

항목을 드래그로 위아래로 이동시키면 실행 순서가 바뀝니다. 자동 큐와 대기·보류 양쪽에서 모두 됩니다.

드래그할 수 있는 항목은 대기 리셋 대기 두 가지뿐입니다. 실행 중이거나 이미 끝난 항목은 순서를 바꿔도 의미가 없어 잠겨 있습니다.

하위로 넣기

드래그한 채 오른쪽으로 이동시키면 바로 위 항목의 하위가 됩니다. 하위로 들어갈 위치에서는 자리 표시가 한 칸 안쪽으로 들어가 보입니다.

전체 항목 표시를 켜 두면 드래그가 잠깁니다. 여러 경로가 섞여 보이는 상태라 경로를 넘나드는 이동을 막기 위한 것입니다. 프로젝트 탭을 하나 고르면 다시 드래그할 수 있습니다.

하위로 넣을 때 지켜지는 규칙

아무 항목이나 하위가 되지는 않습니다. 아래 조건을 모두 만족해야 들어갑니다.

조건이유
옮기는 항목이 경로 대상일 것세션 대상은 이미 특정 세션에 묶여 있어 부모 세션을 이어받을 수 없습니다
바로 위 항목도 경로 대상일 것부모가 될 항목이 세션을 새로 만들어야 그 세션을 물려줄 수 있습니다
옮기는 항목에 하위가 없을 것하위는 한 단계까지만 둡니다. 더 깊어지면 실행 순서를 예측하기 어려워집니다
위 항목이 이미 다른 항목의 하위라면, 그 아래로 들어가지 않고 같은 부모의 형제가 됩니다. 단계가 더 깊어지지 않도록 자동으로 조정합니다.

대화형 터미널과 기록

큐에 맡기기 애매하고 직접 대화해야 하는 작업을 위한 기능입니다.

앱 안에서 터미널 열기

항목을 대화형으로 열면 앱 안에 터미널이 뜹니다. 평소처럼 대화하다가 백그라운드로 계속을 누르면 창을 닫아도 작업이 이어집니다. 다시 열면 재접속됩니다.

출력이 interactive_idle_secs초 동안 멈추면 입력 대기로 보고 알려 줍니다. 기본 8초이며, 0으로 두면 이 알림을 끕니다.

트랜스크립트

실행이 끝난 항목의 전체 기록을 열어 볼 수 있습니다. 무엇을 물었고 어떻게 답했는지 그대로 남으므로, 자리를 비운 사이 실행된 작업도 나중에 확인할 수 있습니다.

설정 레퍼런스

설정 화면은 ⌘,로 엽니다. 표의 항목 대부분은 거기서 바꿀 수 있고, 설정 화면에 없는 네 항목만 아래 경로의 config.toml을 직접 열어 고칩니다. 어느 쪽으로 바꾸든 같은 파일에 저장됩니다.

설정 파일
~/Library/Application Support/com.doitasap.claudequeue/config.toml
잘못 적어도 앱은 뜹니다. 모든 항목에 기본값이 있어 일부만 적어도 되고, 파일이 깨졌으면 .bak으로 백업한 뒤 기본값으로 실행합니다. 허용 범위를 벗어난 값은 가까운 경계로 자동 보정됩니다. 보정한 항목은 설정 화면 위쪽에 배너로 알려 드립니다.
파일을 직접 고칠 때는 앱을 끄고 하십시오. 설정 파일은 앱을 켤 때 한 번 읽습니다. 실행 중에 고친 내용은 다음 실행에야 반영되고, 그 사이 설정 화면에서 저장 버튼을 누르면 화면의 값이 파일을 덮어써 직접 적은 내용이 사라집니다.

max_auto_concurrent_runs31 ~ 20전체 경로에 걸쳐 자동 큐가 동시에 실행할 항목 수입니다. 수동 실행은 세지 않습니다. 자동 큐는 한 경로에서 한 건씩 실행하므로 이 값은 곧 동시에 진행되는 경로 수입니다. 너무 올리면 여러 작업이 같은 토큰 한도를 한꺼번에 소진합니다
max_runs_per_path21 ~ 20같은 경로에서 동시에 허용할 실행 수입니다. 자동과 수동을 합쳐 셉니다. 기본값 2라면 자동 1건이 실행 중이어도 같은 경로를 수동으로 한 건 더 띄울 수 있습니다. 다만 두 작업이 같은 파일을 고치면 서로 덮어쓰니, 파일을 건드리는 작업이라면 1로 낮추십시오
busy_backoff_secs18010 ~ 3600세션 사용 중으로 거부된 뒤, 그 세션을 다시 시도하기까지 기다리는 시간. 설정 화면에는 없습니다
max_busy_retries31 ~ 100거부를 이 횟수만큼 겪으면 실패로 확정합니다. 제한이 없으면 다른 작업이 세션을 놓지 않는 한 계속 기다리게 됩니다. 설정 화면에는 없습니다

두 실행 상한은 세는 대상이 다릅니다. 설정 화면에서는 자동 큐 동시 실행(max_auto_concurrent_runs)과 같은 경로 동시 실행(max_runs_per_path)이라는 이름으로 나옵니다. 경로가 5개인데 max_auto_concurrent_runs가 3이면, 세 경로가 진행되고 나머지 두 경로는 차례를 기다립니다. 반면 max_runs_per_path는 한 경로 안에서만 셉니다.

자동 큐는 한 경로에서 한 건씩만 실행합니다. 같은 프로젝트에서 두 작업이 동시에 파일을 고치면 서로 덮어쓰기 때문입니다. 따라서 max_runs_per_path를 올려 생기는 여유분은 직접 누르는 수동 실행 몫입니다.

두 값을 서로 맞출 필요는 없습니다. 자동 큐가 상한까지 차 있어도 수동 실행 버튼은 그대로 동작합니다.
같은 파일을 두 작업이 고치면 알려 드립니다. 한 경로에서 두 작업이 함께 실행되는 동안 서로 다른 작업이 같은 파일을 고치면 알림이 뜹니다. 다만 이미 벌어진 일을 알려 줄 뿐입니다. 알림이 뜬 시점에는 한쪽이 다른 쪽의 변경을 이미 덮어쓴 뒤입니다. 그렇다고 실행을 중간에 끊으면 파일이 어중간한 상태로 남아 손대기가 더 어려워지므로, 앱은 작업을 멈추지 않습니다.

알림을 받으면 그 경로에서 대화형 터미널을 열어 두 작업을 순서대로 다시 지시하십시오. 애초에 겹치지 않게 하려면 max_runs_per_path를 1로 두면 됩니다.
interactive_idle_secs를 너무 짧게 두지 마십시오. 실측상 작업이 진행 중일 때도 5.6초가량 출력이 비는 구간이 있어, 기본값을 그보다 넉넉한 8초로 잡았습니다. 3초 근처로 낮추면 정상 작업 중에도 입력 대기 알림이 뜰 수 있습니다.

설정 화면에만 있는 것들

시스템 로그인 시 시작

켜 두면 로그인할 때 앱이 메뉴 막대에 떠 자동 큐를 이어서 처리합니다. 이 스위치는 config.toml이 아니라 macOS에 직접 등록됩니다. 설정 파일에 같은 값을 복제해 두면 시스템 설정에서 해제했을 때 두 값이 어긋나기 때문입니다.

claude 실행 확인

확인을 누르면 지정한 실행 파일을 실제로 실행해 보고 버전을 읽어 옵니다. 경로만 적어서는 그 파일이 동작하는지 알 수 없어 둔 버튼입니다.

설정 파일 열기 · 초기화

폴더 열기는 config.toml이 있는 위치를 Finder로 띄웁니다. 초기화는 모든 설정을 기본값으로 되돌립니다. 되돌릴 수 없어 두 번 눌러야 실행되고, 큐 항목과 로그는 지우지 않습니다.

↻ 재시작 표시

이 표시가 붙은 항목은 저장해도 곧바로 듣지 않고 앱을 다시 켜야 반영됩니다. 로그 관련 네 항목이 여기 해당합니다. 나머지는 저장하는 즉시 적용됩니다.

문제 해결

CLI를 찾지 못한다고 나옵니다

앱은 ~/.local/bin/claude를 먼저 보고, 없으면 PATH에서 찾습니다. 둘 다 해당하지 않는 위치에 설치했다면 설정의 claude.bin에 절대 경로를 직접 적으십시오. 터미널에서 which claude로 경로를 확인할 수 있습니다.

"대기 중 · 세션 사용 중"에서 진행되지 않습니다

같은 Claude 세션을 다른 곳이 이미 쓰고 있다는 뜻입니다. 점유 주체는 세 가지이고, 앱이 구분해서 알려 줍니다.

  • 앱 안의 대화형 터미널 — 해당 터미널을 종료하면 풀립니다
  • 큐의 다른 항목 — 그 항목이 끝나면 자동으로 이어집니다
  • 앱 밖의 작업 — 다른 터미널이나 백그라운드 에이전트입니다. 주체를 알아낸 경우 이름까지 표시합니다

설치 후 "손상되었다"거나 개발자를 확인할 수 없다고 나옵니다

공식 배포본은 Apple Developer ID로 서명하고 공증받아 이 경고가 뜨지 않습니다. 이 메시지가 보인다면 내려받은 파일이 손상됐거나 공식 배포본이 아닐 수 있으니, GitHub 릴리스에서 다시 받으십시오.

앱 구조 공시

Anthropic 서드파티 정책 준수를 위해 이 앱의 작동 방식을 명시합니다.

이 앱이 하는 일

  • 사용자 컴퓨터에 설치된 공식 Claude Code CLI를 프로세스로 실행
  • 여러 프로젝트 경로의 작업을 큐에 넣고 정해진 순서 · 예약 시각에 실행
  • 메뉴 막대와 창에서 진행 상황 표시
  • 새 버전이 있는지 확인 — 릴리스 정보만 내려받으며, 보내는 정보는 없습니다

이 앱이 하지 않는 일

  • 인증 정보(OAuth 토큰, API 키) 접근
  • 인증 정보 저장 또는 전송
  • 사용 기록·작업 내용의 외부 전송
  • 사용자 데이터 수집 또는 분석
모든 인증 · 네트워크 통신 · Claude 호출은 공식 Claude Code CLI가 담당합니다. ClaudeQueue는 그 CLI를 언제 어떤 순서로 실행할지만 관리합니다.
